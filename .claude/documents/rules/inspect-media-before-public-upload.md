# 公開の場所へ上げる画像・動画は、機密情報が映り得るものだけ事前に検査する

`puts upload` (bannzai/PUTS。公開 R2 へアップロードして URL を返す) と、gh の `--attach` (`gh pr create` / `gh pr comment` / `gh issue create` / `gh issue comment` が持つ画像・動画のアップロード) は、どちらも画像・動画を自分の手元の外へ出す。`puts upload` はファイルごとの承認なしに実行できるため、渡してよいファイルの限定は本ルールが担う (起票元: https://github.com/bannzai/castle/issues/945 )。

## ルール

- 対象は `puts upload` と gh の `--attach` の両方。どちらの経路でも同じ基準を適用する
- 上げてよいのは画像・動画だけ (撮影した画面、画面録画とその最終フレーム、agent やスクリプトが生成した画像・動画)。設定ファイル・ログ・ソースコード・書き出したデータなど画像・動画以外のファイルは、依頼に含まれていても上げない
- 事前の内容検査が要るのは、機密情報が映り得る対象だけ:
  - パスワード・API キー・トークン・接続文字列を入力・表示する画面 (ログイン・認証設定・secret の登録画面等)
  - 実ユーザーのデータ・個人情報・決済情報が表示される画面、本番環境の管理画面・コンソール
  - ターミナル・ブラウザ・デスクトップ全体など、通知・タブ・別ウィンドウの映り込みがあり得る撮影
  - 自分で撮影・生成していない画像・動画 (Devin 等の外部サービスやワーカーから受け取ったもの)
- 上記に当たらないもの (ダミーデータで動かした通常のアプリ・Web サービスの開発画面、ゲーム画面、スクリプトで生成した動画・画像・図解) は、事前の内容検査なしに上げてよい
- 検査が要る対象の基準と手順は pr-attach-screenshots skill (`~/.claude/skills/pr-attach-screenshots/SKILL.md`「Phase 2: アップロード前の内容検査」) を SSOT とする。動画そのものを上げる時は最終フレームだけでは足りないため、video-frame-reader skill で動画全体のフレームを見るか、検査した静止画だけを上げる
- 検査で公開してはいけない情報が含まれる、または含まれる疑いがあれば上げずに止め、何が映っているか (値そのものは伏せる) を報告してユーザーの判断を仰ぐ。疑いは映っているものを消して撮り直すか、上げない側に倒す
- 承認境界は変えない: 添付が依頼範囲に含まれる (commit-create-pr skill の添付手順・issue の完了条件・ユーザーの依頼) 時に確認なしで進め、依頼に無い公開は `~/.claude/CLAUDE.md`「自律性と確認の境界」に従う
