# サブエージェントの完了報告は状態を分類させ、証拠で確認してから採用する

## 委譲する側が報告に求めること

作業を委譲する時は、報告で次の各項目の状態を答えるよう委譲プロンプトに書く:

- 目標を達成できたか (達成 / 一部だけ達成 / 未達成)。一部だけの場合は、達成した範囲と残った範囲
- エラー・警告・失敗したテストが出ているか。出ていれば、どのコマンドの何の出力か
- 作業途中のものが残っていないか (未コミットの変更、実行中・未完了の処理、後回しにした項目)
- 確認できていない範囲があるか (未検証・未実行のまま成功と推定した箇所)
- 途中でブロックされた・指示と違う方法に変えた箇所があるか、その理由
- 依頼の範囲外に加えた変更があるか
- 成否をそう判断した根拠 (どのコマンドの exit code・どの出力を見たか) と、その出力を記録したログファイルのパス (`./tmp/<タスク名>.log` のように委譲ごとに一意にする)

## 委譲した側が確認すること

- 報告をそのまま成功とみなさない (参照: https://github.com/bannzai/castle/issues/462 )。採用する (ユーザーへ完了報告する・push / PR 作成など次の工程へ進む) 前に、上の各項目を成果物の実物 (差分・生成ファイル) とログ全文で自分で確認する。必要ならサブエージェントのトランスクリプト (`~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`) を見る
- 答えが無い項目は「問題なし」と読まず、実物で確認するか聞き直す
- スキーマの強制が必要な場面では、プロンプト指示の反復ではなく Workflow tool の `schema` オプションを使う
- `tmux send-keys` で agent の pane にプロンプトを送る時も、送信コマンドの成功を到達の証拠にしない (`~/.claude/documents/rules/verify-tmux-send-keys-delivery.md`)
